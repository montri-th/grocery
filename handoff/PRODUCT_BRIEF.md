## ผลิตภัณฑ์ช่วยตัดสินใจอะไร

**ร้านกระจุกที่ไหนเมื่อเทียบกับคน — และพื้นที่ไหนยังมีคนมากกว่าร้าน** ผู้ใช้ต้องเห็นข้อค้นพบที่มีตัวตั้ง ตัวหาร และพื้นที่ที่ถูกนับทันทีที่เปิดหน้า ไม่ต้องตั้งค่าตัวกรองก่อน และถามคำถามเดิมซ้ำได้ทุกระดับด้วยการกดพื้นที่

| ผู้ใช้ (Hypothesis — ดู statement §2.1) | งานที่ต้องทำ | เส้นทางที่ผลิตภัณฑ์รองรับ |
|---|---|---|
| ทีมขยายสาขาของเชนค้าปลีก | เลือกอำเภอ / อปท. สำหรับสาขาใหม่ | Aha ประเทศ → จังหวัด → อำเภอ → อปท. (ต่อ 1 หมื่นคน เทียบค่าอำเภอ) → ตารางสาขา |
| ทีมพัฒนาโครงการ / leasing | ดูร้านรอบโครงการและเลือกเชนที่จะเชิญ | ค้นชื่อพื้นที่/สถานที่ → อปท./ย่าน → ประเภทร้าน + แบรนด์ → สาขาพร้อมแหล่งข้อมูล |
| นักวิเคราะห์ / ที่ปรึกษา / หน่วยงานเมือง | หลักฐานที่ตรวจกลับได้ | กราฟเปรียบเทียบ → ตาราง → รายละเอียดสาขา (แหล่งข้อมูล วันที่ tile) → ลิงก์ CityMETER → JSON |

การเลือกพื้นที่ได้ดีขึ้นเป็นผลที่ต้องวัดกับผู้ใช้ (statement §7) ไม่ใช่ผลที่ผลิตภัณฑ์พิสูจน์แล้ว

## Aha แรก: สาขากระจุกเทียบคน

ที่ระดับประเทศ จังหวัด และอำเภอ แผงเปิดด้วย **ส่วนแบ่งสาขาของพื้นที่ที่ k พื้นที่ย่อยอันดับต้นถืออยู่** เทียบกับ **ส่วนแบ่งประชากรของพื้นที่เหล่านั้น** แผนที่โฟกัส k พื้นที่นั้น (สี ป้าย หมุด) ส่วนอื่นเงียบ ปุ่มหลักคือ “ดูทุก…” (ยกเลิก quiet → `?areas=all`) และ “เปรียบเทียบ…” (เปิดกราฟ) ชื่อพื้นที่ในข้อความเป็นปุ่มเจาะลง

- สูตร: `js/hierarchy.js#buildAha` — เรียงพื้นที่ย่อยตามจำนวนสาขาในตัวกรอง (เท่ากัน → ชื่อ → key) เลือก k = 3 เมื่อมีพื้นที่ย่อย ≥ 9, 2 เมื่อ ≥ 4, ไม่เช่นนั้น 1 (เฉพาะพื้นที่ที่มีสาขา) ตัวเศษคือสาขาของพื้นที่ปัจจุบันที่อยู่ในพื้นที่ใดพื้นที่หนึ่งของ k (union) ตัวหารคือสาขาทั้งหมดของพื้นที่ปัจจุบัน
- ส่วนแบ่งคน = ประชากรของ k พื้นที่ ÷ ผลรวมประชากรของพื้นที่ย่อยทั้งหมด แสดงเฉพาะเมื่อพื้นที่ย่อยทุกแห่งมีประชากร; ขาดแม้แห่งเดียว → “ยังไม่มีข้อมูลประชากรครบทุก… จึงไม่เทียบกับจำนวนคน” (ไม่ประมาณ)
- ข้อความ: `{share}% ของสาขา[ใน{พื้นที่}]อยู่ใน[ k ]{พื้นที่ย่อย}นี้` · `ซึ่งมีคน[แค่] {popShare}% ของ{ระดับ}` — “แค่” เมื่อ round(popShare) < round(share)
- ตัวเลขตั้งต้น (fixture, ไม่ใช่ค่าคงที่ใน markup): **30% (8,228 / 27,607) ใน กรุงเทพมหานคร · ชลบุรี · สมุทรปราการ ซึ่งมีคนแค่ 13%** (8,445,076 / 65,723,008)
- ระดับ อปท./ย่าน ไม่มี Aha: โปรไฟล์บอก “สาขาต่อคนมากกว่า/น้อยกว่า/ใกล้ค่าเฉลี่ยอำเภอ” (`buildUnitInsight`, เกณฑ์ ≥ 1.15 เท่า / ≤ 0.87 เท่า) และอันดับในอำเภอ
- ไม่พบสาขาตามตัวกรอง → “ไม่พบสาขาตามตัวกรองนี้” + ล้างตัวกรอง
- บนมือถือแนวตั้งเมื่อแผงปิด ข้อค้นพบเดียวกันอยู่ในการ์ดย่อบนแผนที่ (มี breadcrumb) ไม่บังคำอธิบายแผนที่

## ตัวชี้วัดและสี

| ตัวชี้วัด | ความหมาย | LDS family | scaleVersion |
|---|---|---|---|
| จำนวนสาขา (`metric=count`, ค่าเริ่มต้น) | สาขาต่อพื้นที่ตามการนับของ production | `count` (dusty cyan → navy) | `4ff5c1fb…0980` |
| ต่อ 1 หมื่นคน (`metric=capita`) | สาขา ÷ ประชากรตามทะเบียน × 10,000 | `density.capita` (salmon → rose) | `0b49c15c…4ab1` |

- quantile สูงสุด 5 ระดับ เหนือพื้นที่ย่อยที่เทียบกัน บนค่าที่ปัดตามที่แสดง (จำนวนเต็ม / ทศนิยม 1 ตำแหน่ง; ต่ำกว่า 0.1 แสดง “<0.1”) ค่าซ้ำลดจำนวนระดับ (`js/scales.js#buildClasses`)

## Basemap, มวลอาคาร และกล้อง

- **Basemap กระดาษ** — `js/map-style.js#buildMapStyle(theme)` สร้าง style v8 บน OpenFreeMap (`https://tiles.openfreemap.org/planet`, OpenMapTiles) สีจาก `--basemap-*` ใน `assets/theme.css` เท่านั้น ป้าย `name:th` ก่อน ไม่มี POI/เลขที่บ้าน/เขตปกครองของ basemap (ขอบเขตมาจากข้อมูลของชุดนี้) ลำดับ: พื้น → น้ำ/สวน → **สีพื้นที่ (ก่อน `waterway`)** → ถนน → **มวลอาคาร (ก่อน `water-name`)** → ป้าย → เส้นพื้นที่ → จุดสาขา
- **มวลอาคาร** — ชั้นเมือง (fill-extrusion จาก tile, `--basemap-massing-quiet`, เฉพาะ 3D, zoom ≥ 13) และชั้นโฟกัสมุมโค้ง (`js/massing.js`, ถอด tile ≤ 9 ใบที่ z14) เฉพาะเมื่อเปิด อปท./ย่านที่กรอบเล็กกว่า 0.08° ความสูงจาก OSM เป็นบริบท ไม่ใช่ข้อมูล ไม่มีอาคารที่ตั้งร้านในชุดนี้
- **กล้อง** (`js/camera.js`) — `plan` (pitch 0) เมื่อปิด 3D, เมื่อกรอบกว้างกว่า 0.3° (ประเทศ จังหวัด และอำเภอที่กว้าง 473 จาก 928 — ไม่มีเขตใดของกรุงเทพฯ) และบนมือถือแนวตั้ง; `city` (pitch 56 / bearing 28) สำหรับภาพรวมของอำเภอ/เขตที่กะทัดรัด; `model` (pitch 60 / FOV 14) สำหรับ อปท./ย่าน สาขา และสถานที่ ทุก preset ไม่ขยับข้อมูล `fitPitched` ปรับ zoom จนทุกจุดยอดของขอบเขตอำเภอ/อปท. ที่เปิด (หรือมุมกรอบเมื่อยังไม่มีขอบเขต) อยู่ในจอที่มี padding; preset `eye` ยังอยู่ในโมดูลแต่ไม่ถูกใช้

## Breadcrumb และ production

แถวบนของแผง: **ประเทศไทย › จังหวัด › อำเภอ/เขต › อปท./ย่าน › สถานที่** (`js/breadcrumb.js`) ชื่อระดับเปลี่ยนตามจังหวัด (กรุงเทพฯ: เขต / ย่าน; อื่น: อำเภอ / อปท.) ร้านเป็นหัวเรื่องของแผง ไม่ใช่ crumb บนจอแคบระดับบนพับหลัง “…” โดยสองระดับสุดท้ายเห็นเสมอ `document.title` = crumbs

ลิงก์ออกไป production (ไม่รับเข้า): `/v3/citymeter?d=grocery` · `/v3/citymeter/{ABBR}?d=grocery` · `/v3/citymeter/{ABBR}/M/{DOLA}?d=grocery` · `/v3/citymeter/{ABBR}/L/{locale uuid}?d=grocery` (production ไม่มี path ระดับอำเภอ) demo ใช้ query `?province=CBI&district=2004&unit=<key>&store=<key8>&place=<GV id>` บน URL เดียว

## กราฟเปรียบเทียบพื้นที่

| key | คำถาม | การเข้ารหัส | สี |
|---|---|---|---|
| `ranking` (count) | พื้นที่ใดมีส่วนแบ่งสาขามากกว่าส่วนแบ่งคน | แท่งคู่ต่อพื้นที่: ส่วนแบ่งสาขา (สีระดับ) + ส่วนแบ่งประชากร (แท่งกลาง ไม่ใช่สีข้อมูล) | ระดับ `count` เดียวกับแผนที่ |
| `ranking` (capita) | พื้นที่ใดมีสาขาต่อคนมากที่สุด | แท่งแนวนอน สาขาต่อ 1 หมื่นคน + จำนวนสาขากำกับ; ไม่มีประชากร = แท่งกลาง “ไม่มีข้อมูลประชากร” | ระดับ `density.capita` |
| `mix` | ประเภทร้านใดอยู่ในพื้นที่ใด | ตารางตัวเลข พื้นที่ (≤ 12) × ประเภทร้าน ทุกช่องขนาดเท่ากัน | ระดับ `count` ของช่อง; 0 = เส้นขอบศูนย์ |
| `brands` | เชนใดอยู่ในพื้นที่ใด | ตารางตัวเลข พื้นที่ (≤ 12) × แบรนด์นำ (≤ 8) ทุกช่องขนาดเท่ากัน | ระดับ `count` ของช่อง |

กราฟเทียบพื้นที่ย่อยของพื้นที่ปัจจุบัน (ระดับ อปท. เทียบพี่น้องในอำเภอ) และไฮไลต์พื้นที่ที่เลือก ทุก mark เป็น `<button>` ส่ง `{type: 'area', level, index}` ไม่มีไลบรารีกราฟ รายละเอียดใน [CHART_SELECTION.md](../docs/CHART_SELECTION.md)
